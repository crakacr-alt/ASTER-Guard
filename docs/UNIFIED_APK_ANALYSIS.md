# ASTER Guard · единая проверка APK (v0.12.0)

## Сценарий из экрана «Лаборатория кода»

1. Откройте **Проверка файла** и выберите APK. ASTER создаст временную копию в своём приватном кэше. Доступ к пользовательским файлам реализован через системный выбор документа.
2. Откройте **Лаборатория кода и трекеров**. Нажмите **Проанализировать код**, чтобы получить результаты DEX: ссылки на рекламные SDK, идентификаторы, SMS, камеру, микрофон, геолокацию, сетевые и загрузочные API. Это ссылки в коде, **не доказательство их выполнения**.
3. Нажмите **Продолжить: анализ поведения APK в Android Lab**. ASTER запомнит **этот же файл** и сформирует ограниченные статические сведения: хэш SHA-256, число классов/методов и ссылки на интересующие API.
4. В Android Lab подключитесь к своему серверу (частный HTTPS, отпечаток сертификата, токен). Теперь вместо повторного выбора APK нажмите **Передать этот APK из лаборатории кода**. Передача файла на сервер требует отдельного подтверждения. APK ещё не установлен.
5. Чтобы запустить эксперимент, необходимо отдельно подтвердить запуск на **изолированном лабораторном компьютере**, настроить и независимо проверить сетевой firewall/NAT для гостя и разрешить запуск в мосте. Сам ASTER не способен доказать безопасность сети.
6. Запустите 15/30/60/120-секундный эксперимент. Root AOSP-эмулятор на ПК сохраняет системный снимок, устанавливает APK, запускает приложение, берёт ограниченные измерения процессов, файлов и гостевых TCP/UDP-сокетов, сохраняет логи и сравнивает состояния.
7. После окончания или отмены ASTER пытается восстановить чистый системный снимок и показывает, подтвердилось ли восстановление. Можно выгрузить **единый JSON/HTML-отчёт**. В него добавляется статический анализ только при совпадении SHA-256 с реально переданным APK.

## Что нового

- На экране DEX анализа добавлена настоящая навигация в Sandbox Analyzer, а не заглушка.
- Выбранный APK передаётся между внутренними экранами без повторного выбора; путь разрешён строго в приватном кэше ASTER.
- Статические DEX-находки и динамическая телеметрия объединяются в **один отчёт** только при проверенном совпадении SHA-256. Поддельный или повреждённый набор статических сведений отклоняется.
- Во время работы гостя дополнительно берутся ограниченные **промежуточные измерения каждые 10 секунд**: видимые метаданные файлов выбранного приложения и гостевые TCP/UDP-соединения. В отчёте различаются сведения о выбранном приложении и **сеть всей гостевой ОС**, которую нельзя автоматически приписать исследуемому APK.
- Отчёты показывают пропущенные/ошибочные измерения и границы наблюдения.

## Что пока НЕ реализовано

**Полная виртуальная Android внутри телефонного APK с root не реализована.** Для настоящего гостя используются официальные инструменты Android Emulator на отдельной машине, а управление находится в ASTER. Современные Android-смартфоны не дают обычному стороннему приложению универсально запустить Android x86/x86_64 с root в полноценной защищённой VM. Shizuku этого не меняет.

Нет гарантии записи абсолютно каждого действия: 10-секундная дискретизация пропускает короткие события; сетевые сокеты не показывают содержимое TLS; полного kernel syscall audit, eBPF, PCAP и восстановления побайтного образа памяти/диска пока нет. Вредоносный код может обнаруживать эмулятор, избегать записи событий или эксплуатировать ошибки виртуализации.

**Автоматизированный анализ настоящих вирусов на живом выделенном хосте не был выполнен в Android CI.** CI проверяет функции на безвредных заглушках, код Java и UI на эмуляторах Android 10/15. Поэтому проект пока является экспериментальной лабораторией, а не подтверждённо безопасным антивирусным «контейнером».
