# ASTER Guard — локальная проверка и установка своей Android Lab

## Режим 1: локально на телефоне

Откройте ASTER → Обзор → Android Lab → **Локально на этом телефоне · без сервера**.

Откроется встроенный файловый анализатор. Он проверяет файл APK, EXE, PDF,
Office, архив или изображение по доступным сигнатурам, вычисляет SHA-256,
обнаруживает некоторые подозрительные элементы, а для APK позволяет
открыть DEX/Smali и лабораторию ссылок на трекеры.

Этот режим **НЕ запускает файл и НЕ создаёт новую виртуальную Android ОС**.
На обычном Samsung/Android APK стороннего разработчика и Shizuku не имеют
универсального публичного API для независимой root VM. Не устанавливайте
подозрительные APK на основной телефон ради анализа.

## Режим 2: своя лаборатория на ПК / VPS

Используйте отдельную Linux x86_64 машину с аппаратным KVM, рекомендуются
8 ГБ RAM, 30 ГБ свободного диска, Ubuntu 22.04/24.04 (Debian также возможен).
Для VPS проверьте наличие /dev/kvm и nested virtualization. Если отсутствует,
автоустановщик откажется запускать эмулятор вместо потенциально
непригодной программной эмуляции.

### Быстрая установка

В терминале отдельного ПК/VPS:

~~~bash
git clone https://github.com/crakacr-alt/ASTER-Guard.git
cd ASTER-Guard
sudo bash lab/auto_setup_server.sh
~~~

По умолчанию HTTPS-мост слушает только 127.0.0.1:8742 **на ПК**. На
телефоне 127.0.0.1 означает сам телефон и **не соединяется с сервером**.

Чтобы подключиться из той же доверенной локальной сети, сначала узнайте
приватный IP ПК (например 192.168.1.100), затем:

~~~bash
sudo bash lab/auto_setup_server.sh --bind 192.168.1.100
~~~

Для Tailscale сначала подключите оба устройства к **вашей** tailnet и
используйте доступный IP 100.64.0.0/10 (пример 100.101.102.103):

~~~bash
sudo bash lab/auto_setup_server.sh --bind 100.101.102.103
~~~

Числа IP здесь только примеры, вводите **фактический** приватный адрес
ПК. Скрипт **не устанавливает Tailscale** и не открывает порт в
публичный интернет. Ограничьте входящий порт 8742 своей доверенной
сетью или VPN; не делайте port forwarding из интернета.

Скрипт:
- устанавливает необходимые пакеты Ubuntu/Debian, проверяет /dev/kvm;
- создаёт отдельного системного пользователя asterlab и даёт доступ
  к группе kvm, не использует root для bridge и emulator;
- загружает официальные Android SDK command-line tools с проверкой
  фиксированного SHA-256 из страницы Android Developers;
- устанавливает rootable AOSP Android API 35 x86_64 (варианты
  --api 24..35, --abi x86|x86_64);
- создаёт AVD, приватный TLS-сертификат и случайный токен;
- регистрирует и запускает два systemd-сервиса: aster-guest и
  aster-bridge. Гостевому сервису дополнительно задан системный
  запрет исходящей сети с исключением loopback. **Это не доказательство,
  что реальный вирус не сможет выйти за пределы гостя.**

При завершении выводятся HTTPS-адрес, SHA-256 сертификата, токен. В
ASTER → Android Lab введите **все три значения**.

### Проверка и обслуживание

~~~bash
sudo systemctl status aster-guest aster-bridge
sudo journalctl -u aster-guest -n 80 --no-pager
sudo journalctl -u aster-bridge -n 80 --no-pager
sudo systemctl restart aster-guest aster-bridge
~~~

Аутентификационные материалы (только на своём ПК):

~~~bash
sudo openssl x509 -in /opt/aster-guard/lab/private/cert.pem -noout -fingerprint -sha256
sudo cat /opt/aster-guard/lab/private/pairing_token
~~~

Не отправляйте токен третьим лицам. Сертификат установщика
самоподписанный и живёт 60 дней; после его обновления надо вручную
проверить и ввести новый SHA-256 в ASTER.

### Особое предупреждение о работе с вирусами

**Автоустановщик не разрешает автоматически запускать подозрительное
ПО.** В ASTER Sandbox Analyzer запуск заблокирован, пока оператор не
настроил отдельную защиту хоста и не подтвердил её проверку.

В systemd guest-сервисе задан IPAddressDeny=any с исключением
localhost, но доступность этой функции и эффективность изоляции
зависят от ядра, systemd, сети и версии Android Emulator. Дополнительно
настроите host firewall/отдельный network namespace, испытайте
отсутствие egress на безвредном тестовом приложении и проверьте журналы
при каждом изменении конфигурации. *Не считайте переменную окружения
проверкой безопасности*.

Только после действительной проверки можно вручную настроить
ASTER_LAB_EGRESS_ISOLATED=YES_I_VERIFIED_HOST_FIREWALL для bridge-сервиса
в отдельном systemd override, затем выполнить daemon-reload и restart.
Скрипт намеренно **не выставляет её сам**. Анализ вредоносных APK
проводите только на отдельном расходном хосте без личных файлов и
аккаунтов. Root-песочница не гарантирует защиту от уязвимостей
гипервизора и ядра.

Для обычных APK без динамического запуска проще и безопаснее
использовать **локальную проверку ASTER на телефоне**.

## Технические ограничения

- Гостевая ОС работает на отдельном ПК/VPS, а не внутри Android APK.
- Автоустановка предназначена для Linux x86_64 с systemd, apt и KVM.
- Обычный VPS без KVM не подходит для этого способа.
- Имеется ограниченная файловая/процессная/сетевая телеметрия и
  снимки до/после; не записываются буквально все системные вызовы.
- Наблюдение и автоматический откат нужно испытывать на конкретном
  выделенном сервере. CI-проверка bash -n не равна тесту реального хоста.
- Скрипт не создаёт ключ подписи релиза ASTER.
